## Claude의 처리 절차

`$MAILMAN_HOME/mailman/local.md`(기본 `~/.claude/mailman/local.md`)가 있으면 먼저 읽고, 그 안의 개인 컨벤션(카드 스타일·말투 등)을 이 문서보다 우선해 따른다. 리액션 정책과 👀 자동 조건도 바꿀 수 있다. 단 **✅ 리액션 사용자 승인·전송 전 사용자 승인·첨부 파일 제한·웹훅 URL 비노출 규칙은 local.md로도 완화할 수 없다.** 없으면 무시한다.

1. 이전 맥락을 포함한 출력 전체를 읽는다. `[새 메시지]`가 이번 조회 대상이며 `[이전 맥락]`은 새 답글을 이해하기 위한 참고다.
2. 다음 내용만 골라 간결하게 요약해 보고한다:
   - API 스펙·스펙 변경. 지금 작업 중인 티켓과의 관련 여부를 함께 판단해 알리고, 관련 스펙은 타입 정의와 요청 작성에 활용한다.
   - 사용자에게 온 요청·질문·확인 요청.
   - 일정·배포 공지처럼 작업에 영향 주는 내용.
3. 잡담·인사·리액션성 메시지는 보고하지 않는다. 보고할 관련 메시지가 없으면 출력 머리의 새 메시지 수를 사용해 **`새 메시지 N건, 작업 관련 없음`** 한 줄로 끝낸다. 이전 맥락을 새 메시지 수에 더하지 않는다.
4. **작업 관련 스펙·요청·핸드오버를 읽고 사용자에게 보고한 뒤** 해당 메시지에 👀를 승인 없이 자동으로 단다. 단순 조회만 하거나 잡담에는 달지 않는다. 리액션은 **해당 내용을 보낸 메시지(스펙·요청·핸드오버 그 자체)**의 `message name`에 단다. 사용자 본인 메시지에는 달지 않는다. `thread_name`을 넣지 않는다. 같은 대상·이모지는 이번 세션에서 한 번만 시도하며 이미 처리한 메시지에 중복으로 달지 않는다. 409/ALREADY_EXISTS의 `이미 있음`은 성공이다.

   ```bash
   ~/.claude/bin/mailman react spaces/SPACE_ID/messages/MESSAGE_ID '👀'
   ```

5. 그 내용을 **실제로 반영 완료**했을 때만 ✅를 준비한다. 대상 메시지 name·내용·✅를 보여 주고 사용자 승인 후 `mailman react <메시지 name> '✅'`를 실행한다. 완료 추정·분석만 수행·미완료에는 달지 않는다. 리액션 권한이 없으면(exit 2) `mailman auth` 재실행을 안내하고 보고/작업은 계속한다. 질문 대기 결과에도 같은 읽기·리액션 절차를 적용한다.

## 동작 모드

- **`/mailman [스페이스]` (기본)**: 수집 후 mailman이 그 방에서 마지막으로 보여준 시점(seen) 이후의 새 메시지를 조회한다. 첫 조회는 최근 24시간이다. seen은 Google Chat 읽음 상태와 무관하다.
- **`/mailman [스페이스] --since 7d`**: 지정 시점 이후를 조회하며 **seen을 바꾸지 않는다**. `24h`, `3d`, `7d` 같은 양의 정수 시간/일 또는 `YYYY-MM-DD`(로컬 자정)를 쓴다.
- **`/mailman [스페이스] --only bot|human`**: 해당 발신자 유형(`BOT`/`HUMAN`)의 새 메시지만 조회하며 **seen을 바꾸지 않는다**(거른 쪽 메시지가 기본 조회에서 사라지지 않게). `--since`와 함께 쓸 수 있다. 같은 스레드의 다른 유형 메시지는 `[이전 맥락]`으로 보일 수 있다.
- **`--with-attachments`**: 표시하는 메시지의 텍스트 첨부를 최대 3개·각 256KB까지 내려받아 파일명·코드블록으로 펼친다. 실패 사유를 표시하고 조회는 계속한다. 개별 첨부는 출력의 `mailman download <메시지 name> --print`로 읽을 수 있다. 기본 저장은 `$MAILMAN_HOME/mailman/attachments/`(파일 0600·디렉터리 0700), 파일당 50MB 상한이며 `--out <디렉터리>`로 바꿀 수 있다. `--out`은 기존 디렉터리 권한을 유지하고 새 디렉터리만 0700으로 만든다. 재사용 기록은 기본 저장 경로에만 두며 `--out`에서는 기록 없이 매번 새 파일로 받는다. Drive 첨부는 링크/ID와 미지원 안내만 표시한다.
- 수집은 최초 최근 7일, 이후 스페이스별 마지막 수집 `createTime` 이후의 증분이다. 수집 커서와 조회 seen은 별개다.
- **`/mailman-deep [스페이스]`**: 수집 커서와 관계없이 **최근 30일 백필 재수집** 후 기본 모드(안 읽은 메시지)로 조회한다. 과거 수정분과 누락된 맥락을 보완하는 용도다. `MAILMAN_BACKFILL_DAYS`로 창을 바꿀 수 있다.
- 새 메시지는 오래된 것부터 최대 200건이다. 더 남으면 기본 조회는 다시 실행해 이어서 보고, 기간 조회는 `--since`를 좁힌다. `--only`만 쓴 조회는 seen을 바꾸지 않아 재실행해도 같은 메시지가 나오므로 `--since`를 지정하거나 좁혀서 나눠 본다. 출력 성공 뒤 실제 보여준 새 메시지의 최대 생성 시각까지 seen을 전진한다. 새 메시지 0건이나 출력 실패에서는 그대로다.
- 백필로 뒤늦게 채워진 과거 메시지(생성 시각이 seen보다 이른 것)는 기본 조회에 **새 메시지로 뜨지 않는다**. 구멍을 메운 뒤에는 `--since`로 그 기간을 확인한다.
- 수집 실패 시에도 기존 DB 내용을 출력하므로 오류 안내와 마지막 성공 수집 시각을 확인한다.

## 저장과 조회 대상

수집 범위는 기본/지정 별칭 또는 해당 호출에서 이름·리터럴·`--dm`으로 선택한 방이다. 미등록 방도 그 호출에서만 사용하며 자동 등록하지 않는다. 그 방의 모든 메시지를 원문 그대로 저장하며 조회도 사람·봇·mailman 전송을 모두 포함한다. 무엇이 중요한지는 Claude가 출력 전체를 읽고 판단한다.

스레드는 가장 이른 새 메시지 시각 기준 오래된 것부터, 내부는 시간순으로 출력한다. 오래된 스레드의 새 답글이면 직전의 저장된 메시지 중 최근 5건을 **이전 맥락**으로 함께 표시하고 나머지 생략 건수도 알린다. 출력 머리의 `thread_name`은 답글 전송에 사용하고 첫 메시지 `name`은 DB 기준이다. 각 메시지의 발신자 표시명과 `(BOT)`/`(HUMAN)` 구분을 참고한다. 수집 창 밖의 과거 원문/답글이 없으면 백필 기간을 늘려야 한다.

DM과 단발 메시지는 시각·발신자·본문·한 줄 `message name`의 시간순 간결 목록이며, 답글용 `thread name`도 한 줄로 표시한다. DM은 실제 스레드도 간결 목록이므로 이전 맥락과 생략 건수를 붙이지 않는다. 그룹 스레드도 각 메시지에 한 줄 `message name`을 표시한다. 그룹의 실제 스레드(2건 이상)는 위 형식을 유지한다. DM의 방 라벨은 `[DM: 이름 또는 users/ID]`, 일반 스페이스는 표시 이름(없으면 별칭/ID)이다. DM 대상 줄은 알면 `DM: 이름 → users/ID`, 모르면 `DM: users/ID` 한 번만 표시하고 대기 중 받은 sender 이름도 반영한다.

`cardsV2`와 구형 `cards`의 카드 본문은 제목·섹션·코드블록·버튼 링크를 포함한 마크다운 텍스트로 펼쳐진다. 텍스트와 카드가 함께 있으면 텍스트가 먼저 나온다. 멘션과 카드가 별도 메시지여도 같은 스레드에 저장되어 있으면 둘 다 표시한다.

사용자가 "특정 발신자 메시지만 보여줘" 같이 요청하면 `/mailman` 결과에서 발신자 기준으로 필터링해서 보여주면 된다.

## 대상 찾기

**스페이스 ID를 사용자에게 묻지 않는다.** config 별칭 → `spaces/ID` → `--dm <사람>` → 스페이스 표시 이름 순으로 해석한다. 생략하면 `defaultSpace`다. 모르는 방은 `~/.claude/bin/mailman spaces '검색어'`로 찾고 필요하면 `--refresh`로 갱신한다. DM은 `--dm colleague@example.test`, `--dm '사람 이름'`, `--dm users/USER_ID`를 쓴다. 사람 이름은 수집된 발신자 기록에서 유일해야 하며, 없거나 동명이인이면 이메일로 구분한다. 기존 DM만 찾고 만들지 않는다.

이름은 대소문자·공백을 무시한 정확 일치 우선, 없으면 부분 일치다. **후보가 여러 개면 이름·종류·ID 목록을 그대로 보여 주고 사용자에게 고르게 한다. 임의로 고르지 않는다.** 위치 인자와 `--dm`은 함께 쓰지 않는다. `--save <새 별칭>`을 명시할 때만 저장하고 기존 별칭을 덮어쓰지 않는다.

모든 출력 첫 줄의 `[대상] 이름 (종류, spaces/...)`를 확인한다. 전송 초안에는 이 해석된 대상의 **이름·종류·ID를 반드시 표시**한다. `send --dry-run`에 승인 전 초안을 stdin으로 넣어 태그와 대상 미리보기를 확인할 수 있다. 별칭/리터럴이 `SPACE_TYPE_UNSPECIFIED`라면 `spaces --refresh`로 실제 표시 정보를 확인한 뒤 미리보기에 반영한다.

최초 인증은 `~/.claude/bin/mailman auth --client <다운로드한 client_secret JSON>`([설정 가이드](https://thewronghand-bigs.github.io/mailman/setup) 참조). 토큰이 없거나 `invalid_grant` 안내가 나오면 `~/.claude/bin/mailman auth`(`--client` 없이)로 다시 인증한다.

## 작업 완료 시 Google Chat 전송 (승인 필수)

이 `/mailman` 세션에서 가져온 API 스펙을 바탕으로 실제 구현/수정 작업을 진행했고,
그 작업이 완료된 시점에 다음을 수행하라:

1. **요약 초안 작성** — 아래 포맷으로 간결하게 작성:
   ```
   [작업 완료 알림]
   도메인: {파악된 경우}
   변경 요약:
   - {핵심 변경 1}
   - {핵심 변경 2}
   변경 파일:
   - path/to/file1
   - path/to/file2
   남은 이슈/질문: {있는 경우만, 없으면 "없음"}
   ```
   5~10줄 이내. 불필요한 수식어 금지.

2. **사용자 승인 요청** — 초안을 출력한 뒤 "이 내용으로 Google Chat에 전송할까요?" 라고 묻는다.
   승인 전에는 절대 전송하지 않는다. 수정 요청 시 반영 후 재승인 요청.

3. **전송 실행** — 승인되면, 메시지를 가져온 스페이스로 전송:
   ```
   cat <<'MAILMAN_EOF' | ~/.claude/bin/mailman send [스페이스별칭] --agent claude
   [초안 내용]
   MAILMAN_EOF
   ```
   `mailman send`는 **OAuth로 로그인한 사용자 명의**로 보내며, 본문 앞에 `[🤖 Claude] `(Codex는 `[🤖 Codex] `) 태그가 붙는다. 사용자가 설정에서 끈 경우(`sendTag: false`) 태그 없이 나간다. 초안 미리보기에도 이 태그와 `[대상] 이름 (종류, ID)`, 대상 스레드를 명시한다.

   원 스레드에 답글을 달려면 출력의 `thread name`(스레드 머리에서는 `thread_name`) 값을 `--thread`에 쓴다. 값이 `(없음)`이면 스레드 ID를 추측하지 않는다:
   ```bash
   cat <<'MAILMAN_EOF' | ~/.claude/bin/mailman send [스페이스별칭] --agent claude --thread spaces/SPACE_ID/threads/THREAD_ID
   [초안 내용]
   MAILMAN_EOF
   ```
   태그를 본문에 직접 중복해서 넣지 않는다. API가 해당 스레드에 답글을 달 수 없으면 새 스레드로 전환한다.
   `✅ 전송 완료`와 생성된 message/thread 이름 확인 후 보고한다. 실패 시 재시도하지 않고 알린다.

## 파일 첨부 전송 (승인에 포함)

`send --attach <파일>`을 반복해 최대 10개·각 200MB 이하 일반 파일을 보낸다. 심볼릭 링크 파일은 거절한다. 중간 디렉터리 링크는 허용하되 미리보기·성공 출력에는 realpath로 해석한 실제 경로를 표시한다. **사용자가 지정하지 않은 파일은 첨부하지 않는다. .env·키·토큰·자격증명 파일은 첨부하지 않고 사용자에게 경고한다.** 관련 있어 보이는 레포 파일이나 내려받은 첨부도 임의로 추가하지 않는다.

핸드오버 md를 작성해 보내 달라는 요청은 먼저 파일로 쓴 뒤 그 경로를 첨부한다. 전송 전에 `--dry-run`으로 대상·본문과 **모든 첨부의 경로·이름·크기**를 보여 주고 이 목록까지 포함해 사용자 승인받는다. 승인 후 파일 목록/내용이 바뀌면 다시 미리보기와 승인을 받는다.

```bash
~/.claude/bin/mailman send [대상] --agent claude --attach ./handover.md --dry-run < /dev/null
# 위 파일 경로·이름·크기와 대상에 대한 사용자 승인 후:
~/.claude/bin/mailman send [대상] --agent claude --attach ./handover.md < /dev/null
```

본문을 넣을 때는 기존처럼 stdin을 사용한다. 비어 있고 첨부가 있으면 태그만, 태그를 끄면 텍스트 없이 첨부만 보낸다. `--thread`·`--wait`와도 조합할 수 있다. 모든 파일 검증과 업로드가 끝나야 메시지를 생성한다. 업로드 실패/중단이면 메시지 미전송·기존 업로드 무시 안내를 보고하며, 재시도하지 않는다. 업로드 중단은 메시지 생성 POST 전이므로 전송 여부 불확실/exit 5가 아니다. 성공 출력의 첨부 이름 목록과 실제 경로도 확인한다. 403이면 기존 chat.messages.create 권한과 mailman auth 재실행을 안내하며 스코프를 추가하지 않는다.

## 텍스트 전송 서식

사용자 명의 메시지는 **마크다운**(`MARKUP_SYNTAX_MARKDOWN`)으로 해석된다. 웹훅·봇의 Chat 전용 문법과 다르다. 2026-10-22 실제 전송으로 확인한 결과:

- **줄바꿈 한 번은 무시되고 앞 줄에 이어 붙는다.** 문단을 나누려면 빈 줄을 넣는다.
- `*텍스트*`·`_텍스트_` → 기울임. 굵게는 `**텍스트**`(표준 마크다운 기준, 미검증).
- `~텍스트~` → 취소선, `` `코드` `` → 인라인 코드, ```` ``` ```` 블록 → 코드블록(줄바꿈 유지).
- `- 항목` → 글머리표 목록.
- `<url|라벨>` 링크 문법은 **동작하지 않는다**(글자 그대로 노출). URL은 그대로 쓰면 자동 링크된다. 라벨 링크가 필요하면 `[라벨](url)`(미검증).
- `<users/USER_ID>` → 실제 멘션(알림 발생).
- 앱 구성 이름(`mailman`)이 발신자 옆에 표시된다.

## 카드(Cards v2) 형식으로 보내기

사용자 OAuth는 `cardsV2`를 보낼 수 없다. `mailman send`는 텍스트·파일 첨부를 지원하며, 카드는 **`curl`로 webhook URL에 직접 POST** 한다 (`webhookUrl`은 설정 파일 `~/.claude/mailman/config.json`의 해당 스페이스에서 꺼낸다). 웹훅 URL은 터미널/로그에 출력하지 않는다. 카드 스타일(제목·헤더 이미지·섹션 구성·색상)은 `local.md`에 개인 컨벤션이 있으면 그것을 따른다.

### 최소 페이로드 예시

```bash
MAILMAN_CONFIG_FILE="${MAILMAN_CONFIG:-${MAILMAN_HOME:-$HOME/.claude}/mailman/config.json}" && \
WEBHOOK=$(plutil -extract spaces.team.webhookUrl raw -o - "$MAILMAN_CONFIG_FILE") && \
curl -sS -X POST "$WEBHOOK" -H 'Content-Type: application/json; charset=UTF-8' -d @- <<'EOF'
{
  "cardsV2": [{
    "cardId": "<짧은-식별자>",
    "card": {
      "header": {
        "title": "<제목>",
        "subtitle": "<부제목>"
      },
      "sections": [
        {
          "header": "변경 사항",
          "widgets": [
            { "textParagraph": { "text": "<b><핵심 한 줄 요약></b><br>• <세부 1><br>• <세부 2>" } }
          ]
        }
      ]
    }
  }]
}
EOF
```

`spaces.team`의 `team`은 승인받은 전송 대상 별칭으로 바꾼다. macOS 기본 `plutil`로 JSON 설정을 읽으므로 bun이 없어도 된다. `WEBHOOK` 변수 값 자체는 출력하지 않는다. 헤더 이미지(`imageUrl`)·섹션 추가 등은 [Cards v2 규격](https://developers.google.com/workspace/chat/api/reference/rest/v1/cards)을 따른다.

`textParagraph.text`에서 허용되는 HTML은 `<b>`, `<i>`, `<u>`, `<s>`, `<font color="#hex">`, `<a href>`, `<br>` 뿐이다. CSS / 그라디언트 / 폰트 크기 / 폰트 패밀리는 **불가**하다.

### 전송 절차 (승인 필수)

1. **카드 페이로드 초안 작성** — 위 예시(또는 `local.md`의 카드 컨벤션)를 채워서 사용자에게 미리보기 (JSON 형태로) 한다. 해석된 대상의 이름·종류·ID도 표시한다.
2. **사용자 승인 요청** — "이 내용으로 Google Chat에 전송할까요?" 묻기. 톤/문구/이모지 변경 요청 시 반영 후 재승인.
3. **전송 실행** — `curl` 명령으로 발사. webhook 응답에 `"name": "spaces/..."` 가 보이면 성공.

## 백엔드에 질문 보내기 (승인 필수)

작업 중 API 스펙에 대해 궁금한 점이 생기면 (nullable 여부, 필드 의미, 예외 케이스 등)
사용자가 "이거 물어봐", "백엔드한테 질문해" 같은 요청을 할 수 있다.

1. **질문 초안 작성** — 아래 포맷으로 간결하게:
   ```
   [API 스펙 질문]
   대상 API: {method} {path}
   질문:
   - {질문 1}
   - {질문 2}
   ```
   맥락이 필요하면 "배경: ..." 한 줄 추가. 장문 금지.

2. **사용자 승인 요청** — "이 내용으로 Google Chat에 전송할까요?" 묻기.
   승인 전에는 절대 전송하지 않는다.

3. **전송과 답장 대기** — 답장이 필요한 질문은 승인 후 `send --wait`를 쓴다. 원 스레드에 답하려면 `--thread`를 추가하고, 특정 사람 답장만 원하면 `--from <사람>`을 쓴다:
   ```
   cat <<'MAILMAN_EOF' | ~/.claude/bin/mailman send [대상] --agent claude --wait --quiet 60s --timeout 30m --interval 15s
   [초안 내용]
   MAILMAN_EOF
   ```

   **Claude Code에서는 위 Bash 도구 호출에 `run_in_background: true`를 지정**해 둔다. 셸의 `&`만 붙이지 않는다. 완료 알림이 오면 해당 작업의 출력 전체를 읽고, 짧게 이어진 답장을 한 묶음으로 이해한 뒤 구현·확인 작업을 이어 간다. 첫 답장 후 최대 10분/전체 timeout 중 빠른 시점에도 묶음을 반환한다. 질문을 다시 전송하지 않는다.

   대기 전 안 읽은 메시지가 있으면 먼저 표시하고 이어서 `답장 N건(조용해진 뒤 묶음)`을 표시한다. 답장 없음은 exit 4이므로 질문은 이미 전송됐다는 사실과 함께 보고하고 재전송하지 않는다. **`send --wait`가 exit 5면 전송은 완료됨 — 재전송 금지.** 대기 오류·출력 실패·전송 후 SIGINT/SIGTERM도 exit 5다. 전송 요청 중 중단은 전송 여부가 불확실하므로 Chat에서 확인 후 재전송 여부를 판단한다. 단독 `wait`의 SIGINT/SIGTERM은 130/143이다. `--from`·`--thread` 대기, 대기 오류, 출력 실패, 중단은 seen을 유지한다. 이미 보낸 질문은 `~/.claude/bin/mailman wait [대상] --timeout 30m`으로 새 실행 시각부터 기다릴 수 있다.

   `--timeout` 상한은 2시간이다. 연결 오류·5xx·429는 최대 60초 백오프로 재시도하고, 연속 실패 5분이면 받은 답장까지 출력한다. 401은 토큰 갱신 후 1회 재시도한다. `--from`은 전송 전에 확정하며 이메일은 기존 DM의 수집 기록 또는 최근 메시지에서 상대 ID를 찾는다(기본 7일, `MAILMAN_BACKFILL_DAYS` 적용). DM이 없거나 ID를 확정하지 못하면 전송하지 않는다. 그때는 수집된 정확한 이름이나 users/ID로 지정한다.

   빈 대상·`--dm`·`--from`·`--save`는 인자 오류다. 이름 캐시는 24시간 초과 시 자동 갱신하며 실패하면 경고 후 기존 캐시를 쓴다. DM 미리보기의 해석된 users/ID를 확인한다. `--dry-run --save`는 저장할 예정 안내만 하고 config를 바꾸지 않는다.

질문도 사용자 명의로 나가며, 본문 앞에 `[🤖 Claude] `(Codex는 `[🤖 Codex] `) 태그가 붙는다. 사용자가 설정에서 끈 경우(`sendTag: false`) 태그 없이 나간다. 태그와 해석된 대상의 이름·종류·ID/스레드를 초안에 표시하고, 전송 본문에는 태그를 중복해서 넣지 않는다. 사용자가 명시적으로 요청한 경우에만 질문을 보낸다. 자의적으로 질문을 생성하지 않는다.

## 공통 예외

- `/mailman`과 무관한 다른 작업 중에는 위 전송 절차들을 적용하지 않는다.
- 코드 수정 없이 분석만 한 경우 "변경 파일: 없음 (분석만 수행)"으로 명시.
- 조회 결과가 "[별칭] 새 메시지가 없습니다." 또는 "수집된 데이터가 없습니다. 먼저 mailman auth 및 mailman collect를 실행하세요."인 경우 아무 것도 하지 않는다. 스페이스 별칭이나 뒤의 메타 정보가 함께 출력되어도 같다.
